    한계와 빠진 것¶

    이 쪽에서 알 수 있는 것

    • 알려진 약점 가운데 고친 것(무엇을 · 어떻게)
    • 판정이 달라질 수 있어 기본값은 그대로 두고 선택지로만 넣은 것
    • 이 저장소에서 못 고치는 것과 이유, 이 저장소에 없는 것

    원칙¶

    • 이 코드는 이미 제출한 데이터셋의 실패 / 통과를 만든 코드 → 기본 동작의 판정 값 · 판정 사유 문장은 바꾸지 않음
    • 확인 방법: 리팩토링 전 · 후 코드에 같은 입력을 넣어 결과를 행 단위로 비교(골든 비교)
      • 실제 자료로: 규칙 판정 · 판정 집계 결과의 모든 열 차이 0(이 저장소 밖에서 돌림, 자료는 올리지 않음)
      • 지어낸 예시로: tests/test_regression.py가 리팩토링 전 코드의 결과(tests/expected/)와 비교

    • 넣지 않은 것과 이유
    약점 이유
    펀웨이브는 근거충실성만 판정 모델 결과를 씀 나머지 평가 항목(개인정보 · 유해 · 다국어 · 인젝션 · 반복)의 기준은 "막았나 · 점수가 문턱을 넘었나"라서 판정 모델이 볼 몫이 없음. 판정 모델은 통역 충실도만 냄
    정답 · 거절 표현을 글자로 비교 글자로 못 잡은 행은 이미 검토필요로 넘겨 판정 모델이 다시 봄. 규칙 단계에 뜻 비교를 넣으면 판정 모델 호출이 필요해져 "외부 호출 없음 · 늘 같은 결과"라는 규칙 판정의 성질이 깨짐

    못 고치는 것과 이유¶

    약점 왜 이 저장소에서 못 고치나
    문턱 값(40 · 70 · 85점, 10 · 20점 범위, 15점 차이, 충실도 39 · 60 · 85)의 근거 근거는 기업 답변서 · 평가 설계 문서(이 저장소 밖, 기업 제공 문서라 올릴 수 없음). 코드에서는 이름 붙은 상수로 모아 둠(기업별 판정 기준)
    펀웨이브 근거충실성의 기대 범위 값이 입력 자료의 열(expected_meaning_range · expected_final_range)에 있음. 값을 정하는 문항 생성 단계는 이 저장소 범위 밖
    서비스 고정 문구(자료 인용 머리말 · 정형 유보문)를 글자 그대로 비교 기준이 되는 문구는 기업 서비스가 정함. 서비스가 문구를 바꾸면 이 코드도 같이 바꿔야 함(src/report/rules/actibuki.py:35-37)
    정제본 · 제외 분류 제출 양식 · 지식베이스 내용과 얽혀 있어 이 저장소에 없음

    남은 한계¶

    • 판정 모델 출력은 형식 강제에 기댐 — 형식이 어긋나면 이제 502로 알리지만, 값의 옳고 그름은 판정 모델 몫
    • 호출 원본이 로컬에 쌓임 — raw/ 아래 요청 · 응답 전문(문항 · 응답 원문 포함). 공유 · 커밋 금지(.gitignore 대상)
    • 가짜 판정 모델은 판정 품질과 무관 — 흐름 · 형식 확인용
    • 엔드포인트 문서의 응답 예시는 손으로 씀 — 오류 응답(401 · 404 · 405 · 422 · 502)만 시험 클라이언트로 받은 실제 값
    • 확인 범위 — 실제 판정 모델 호출은 이 저장소에서 다시 돌려 보지 않음(가짜 판정 모델 · 기록해 둔 판정 결과로만 확인)

    이 저장소에 들어 있지 않은 것과 이유¶

    빠진 것 이유
    문항 생성 유해 요청 문장 · 욕설 목록이 들어 있음. 판정 범위 밖
    품질 검사(중복 · 결함 거르기) 판정 범위 밖
    기업 API 호출 기업 API 주소 · 호출 방식이 들어 있음. 이 저장소는 받아 둔 응답만 읽음
    수치 계산 여러 응답을 세는 단계. 정제본 기준 공식 수치와 다르게 나올 수 있어 혼동 방지
    정제본 · 제외 분류 · 엑셀 제출 양식과 얽혀 있고 지식베이스 · 문항 내용이 섞여 있음
    판정 대상 줄이기 · 묶음 실행 보조 도구 판정 모델 사용 한도 때문에 운영 중 쓰던 도구. 판정 기준과 무관
