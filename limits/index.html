    한계와 빠진 것¶

    한계 · 알려진 약점¶

    • 판정 표기가 공격 쪽 말 — 코드 · 열 이름 · 판정 사유 문장의 판정 값이 서비스 쪽 표기와 반대 방향. 용어 풀이의 대응표대로 바꿔 읽어야 함
    • 문자열 비교의 한계(액티부키 규칙)
      • 정답 · 틀린 값을 글자 일치로 찾음 — 다른 말로 풀어 쓴 답은 놓침 (src/report/rules.py:427-448)
      • 거절 · 부정 표현을 정해진 목록으로 찾음 — 목록에 없는 말투는 놓침 (:343, :345)
    • 서비스 고정 문구에 의존 — 자료 인용 머리말과 정형 유보문을 글자 그대로 비교함 (src/report/rules.py:347-348). 서비스가 문구를 바꾸면 규칙 결과가 달라짐
    • 액티부키는 모델 결과가 규칙 결과를 덮어씀 — 규칙이 확정한 행도 모델 결과가 있으면 모델 판정을 씀(판정 흐름). 모델 오판이 그대로 최종 판정이 됨
    • 판정 모델은 1회차 기준 — 2회 결과가 달라도 판정은 1회차로 내고 흔들림 표시만 남김 (src/report/verdict.py:105-115, :520-528)
    • 펀웨이브는 근거충실성만 모델 결과를 판정에 씀 — 실행기는 반복 · 다국어 · 인젝션 행도 모델에 보내지만 판정 집계는 그 결과를 판정 값에 쓰지 않음(인젝션은 사유 문장에 참고로만 붙임) (src/judge_api/run_judge.py:31 · src/report/verdict.py:294-298)
    • 문턱 값은 코드 상수 — 40 · 70 · 85점, 10 · 20점 범위, 15점 차이, 충실도 39 · 60 · 85 등. 근거가 된 기업 답변서 · 평가 설계 문서는 이 저장소에 없음. 문턱 사이 값은 검토필요로 남음
    • 기대 범위는 입력 자료에 들어 있음 — 펀웨이브 근거충실성 규칙은 expected_meaning_range · expected_final_range 열 값에 기댐. 값을 정하는 문항 생성 코드는 이 저장소에 없음
    • 사본 프롬프트 누락 — 서버가 써 내는 prompts/judge_rubric_actibuki.md에 유해 질의용 출력 형식이 빠져 있음(src/judge_api/app.py:206의 목록에 harm이 없음). 실제 호출에는 app.py:131의 형식을 씀
    • 호출 원본이 로컬에 쌓임 — 판정 모델 요청 · 응답 전문이 raw/ 아래 파일로 저장됨 (src/common/core.py:225-226). 문항 · 응답 원문이 들어가므로 공유 · 커밋 금지(.gitignore 대상)
    • 확인 범위 — 이 저장소 기준으로는 문법 검사 · import · --help · 지어낸 소규모 자료로 규칙 판정 → 판정 집계까지만 확인함. 실제 판정 모델 호출은 이 저장소에서 다시 돌려 보지 않음
    • 판정 서버에 인증이 없음 — 로컬(127.0.0.1)에서만 띄울 것(공통 사항)
    • 엔드포인트 응답 형식이 OpenAPI에 없음 — /openapi.json에는 요청 형식만 있고 응답은 빈 형식({}). 응답 필드는 이 문서의 표(코드에서 확인)를 볼 것
    • 판정 모델 출력은 형식 강제에 기댐 — 판정 모델 API가 JSON 형식 강제(strict JSON schema)를 지키지 않으면 필수 키가 빠질 수 있고, 이때 서버가 500을 낼 수 있음(코드 읽기로만 확인, src/judge_api/app.py:351)
    • 이 문서의 응답 예시는 실제 호출 결과가 아님 — 판정 모델을 부르지 않고 코드의 응답 구조대로 손으로 씀. 오류 응답 422 · 404 · 405는 FastAPI TestClient로 받은 실제 값

    이 저장소에 들어 있지 않은 것과 이유¶

    빠진 것 원 작업 폴더 위치 이유
    문항 생성 src/gen/, prompts/gen_*.md 유해 요청 문장 · 욕설 목록이 들어 있음. 판정 범위 밖
    품질 검사(중복 · 결함 거르기) src/dedup/ 판정 범위 밖
    기업 API 호출 src/infer/ 기업 API 주소 · 호출 방식이 들어 있음. 판정 범위 밖
    수치 계산 src/report/metrics.py 응답 하나의 판정이 아니라 여러 응답을 세는 단계. 호출 단위로 세며 검토필요 · 제외 문항까지 포함해, 정제본 기준 공식 수치와 다르게 나옴(혼동 방지). 문턱 값은 rules.py와 겹침
    정제본 · 제외 분류 · 엑셀 report/tta_format/build_clean_dataset.py 등 엑셀 양식 · 제출 서식과 얽혀 있고 지식베이스 · 문항 내용이 문구에 섞여 있음. 그래서 "제외" 세부 분류는 이 저장소에서 확인할 수 없음
    판정 대상 목록 만들기 · 묶음 실행 scripts/judge_clean_ids.py, scripts/judge_batches_v2.sh 판정 모델 사용 한도 때문에 실제 운영에서 대상 문항을 줄이던 보조 도구. 판정 기준과 무관
    반복 안정성 정답 값 재확인 scripts/judge_repeat_calls.py 실행기와 명령의 보조 파일(data/repeat_kb_semantic_actibuki.jsonl)을 만드는 도구. 없으면 규칙 판정은 문자열 비교만으로 돎
    프롬프트 사본 prompts/judge_*.md 판정 서버가 시작할 때 app.py 안의 문자열로 다시 써 내는 사본(읽지 않음). 모델 이름이 들어감
