    실행기와 명령¶

    이 쪽에서 알 수 있는 것

    • 세 단계를 돌리는 명령(Makefile 목표 · 파이썬 모듈)과 선택지
    • 판정 집계의 선택지(--judge-policy · --keep-rule-verdicts)와 기본값
    • 환경 변수 전체 목록

    무엇 · 왜¶

    • 기업 응답 파일 하나를 세 단계로 판정하는 명령 모음
    • 모든 명령은 저장소 최상위 폴더에서 실행(python -m src.... 꼴)
    • <기업> = funwave(펀웨이브) 또는 actibuki(액티부키)
    • 기업 API는 어느 명령도 부르지 않음
    flowchart LR
    I["data/inference_기업.parquet<br/>(미리 받아 둔 기업 응답)"] --> R["make rules"]
    I --> J["make judge<br/>(판정 서버 필요)"]
    R --> RO["data/rules_기업.parquet"]
    J --> JO["data/judge_기업.parquet"]
    RO --> V["make verdict"]
    JO -. "있으면 읽음" .-> V
    V --> VO["data/verdict_기업.parquet"]

    Makefile 목표¶

    목표 하는 일 외부 호출
    make venv .venv 만들고 requirements.txt 설치 패키지 설치만
    make venv-dev 위 + requirements-dev.txt(pytest · ruff) 패키지 설치만
    make demo 예시 입력으로 ① → ②(가짜 판정 모델) → ③. 결과 build/demo/ 없음
    make demo-rules 예시 입력으로 ① → ③ 없음
    make rules VENDOR=<기업> ① 규칙 판정 없음
    make judge-up · make judge-down 판정 서버 켜기(127.0.0.1:PORT, 기본 8787) · 끄기 —
    make judge VENDOR=<기업> CALLS=2 ② 켜 둔 판정 서버로 판정 모델 호출 판정 모델 API
    make judge-offline VENDOR=<기업> ② 가짜 판정 모델 · 같은 프로세스 안 판정 서버 없음
    make verdict VENDOR=<기업> JUDGE_POLICY=first ③ 판정 집계 없음
    make all VENDOR=<기업> rules → judge → verdict(판정 서버는 먼저 켜 둘 것) 판정 모델 API
    make test · make lint 회귀 시험 · 코드 검사(ruff · compileall) 없음

    ② 판정 모델 호출(실행기)¶

    python -m src.judge_api.run_judge --vendor {funwave,actibuki} [선택지]
    선택지 기본값 뜻
    --input <데이터 폴더>/inference_<기업>.parquet 기업 응답 파일
    --out <데이터 폴더>/judge_<기업>.parquet 결과 파일
    --calls-per-case 2 문항마다 판정 횟수
    --limit N 없음 앞에서부터 N 문항만(액티부키는 일반 · 변형 각각 N)
    --case-ids A B … 없음 이 문항만(액티부키 변형만 골라도 짝이 되는 원문은 전체에서 찾음)
    --no-meta 꺼짐 펀웨이브 불일치 원인 분류(/judge/meta) 건너뜀
    --force 꺼짐 기존 결과 파일을 무시하고 처음부터
    --start · --cap 4 · 16 판정 서버 동시 호출 수 시작값 · 상한
    --judge-url JUDGE_API_URL 또는 http://127.0.0.1:8787 판정 서버 주소
    --in-process 꺼짐 판정 서버를 포트 없이 같은 프로세스에서 부름
    --cache-only 꺼짐 raw/judge_client/에 남은 결과만 되살리고 새 호출은 안 함
    • 근거: src/judge_api/run_judge.py:319-334
    • 시작할 때 /ping이 실패하면 judge API not reachable로 멈춤 (src/judge_api/run_judge.py:354-356)

    무엇을 어디로 보내나¶

    기업 고르는 행 엔드포인트 근거
    펀웨이브 HTTP 200 · 필터에 막히지 않음 · 평가 항목이 근거충실성 · 반복 강건성(첫 회차만) · 다국어 · 인젝션 /judge/faithfulness src/judge_api/run_judge.py:159-168
    펀웨이브 위 1회차 결과가 "적정 + 동일상황"이 아닌 문항 /judge/meta(1번) src/judge_api/run_judge.py:268-287
    액티부키 HTTP 200인 행(문항마다 첫 회차) 중 입력 강건성 변형이 아닌 것 /judge/rubric/actibuki src/judge_api/run_judge.py:171-181
    액티부키 입력 강건성 변형(같은 묶음 원문과 짝지음) /judge/robustness src/judge_api/run_judge.py:204-208

    이어서 돌리기¶

    • 결과 파일에 이미 성공으로 있는 (문항, 회차, 판정 횟수, 엔드포인트)는 다시 부르지 않음 (src/judge_api/run_judge.py:347-352)
    • raw/judge_client/에 HTTP 200 결과가 남은 호출도 되살림 (src/judge_api/run_judge.py:248-265)
    • 실패했다가 다시 성공한 호출은 성공 기록만 남김 (src/judge_api/run_judge.py:308-314)

    만드는 파일¶

    파일 내용
    judge_<기업>.parquet 판정 서버 호출 1번 = 1행(열 설명)
    logs/judge_<기업>_run.md 실행 요약(호출 수 · 성공 · 오류)
    raw/judge_client/*.json 판정 서버 요청 · 응답 원본

    ③ 판정 집계¶

    python -m src.report.verdict --vendor {funwave,actibuki} [--judge-policy {first,agree}] [--keep-rule-verdicts]
    선택지 기본값 뜻 켜면
    --judge-policy first first 판정 모델을 여러 번 돌린 문항은 1회차 결과로 판정. 회차별 판정이 갈리면 judge_flip 표시만 —
    --judge-policy agree — 회차별 판정이 갈린 문항은 검토필요 제출한 데이터셋 판정과 달라질 수 있음
    --keep-rule-verdicts 꺼짐 (액티부키) 규칙이 실패 · 통과로 정한 행은 판정 모델 결과를 쓰지 않음 제출한 데이터셋 판정과 달라질 수 있음
    • 근거: src/report/verdict/__main__.py:19-24, 처리 src/report/verdict/__init__.py:76-121
    • 읽는 파일: rules_<기업>.parquet(필수) · judge_<기업>.parquet(없으면 규칙 결과만) · actibuki_kb_sites.json(있으면 지식베이스 속성 이름을 사유에 씀)
    • 만드는 파일: verdict_<기업>.parquet(열 설명)
    • 판정 모델 결과와 맞추는 열쇠: (case_id, run, 엔드포인트). 입력에 run 열이 없으면 실행기 · 판정 집계 모두 "1"을 씀 (src/common/config.py:19)
