    실행기와 명령¶

    • 기업 응답 파일 전체를 세 단계로 판정하는 명령
    • 모든 명령은 저장소 최상위 폴더에서 실행
    • <기업> = funwave(펀웨이브) 또는 actibuki(액티부키)
    flowchart LR
    I["data/inference_기업.parquet"] --> R["make rules<br/>rules.py"]
    I --> J["make judge<br/>run_judge.py<br/>(판정 서버 필요)"]
    R --> RO["data/rules_기업.parquet"]
    J --> JO["data/judge_기업.parquet"]
    RO --> V["make verdict<br/>verdict.py"]
    JO -. "있으면 읽음" .-> V
    V --> VO["data/verdict_기업.parquet"]

    Makefile 목표¶

    목표 하는 일 실제 명령 근거
    make venv .venv를 만들고 requirements.txt 설치 python3 -m venv .venv && .venv/bin/pip install ... Makefile:10-11
    make rules VENDOR=<기업> ① 규칙 판정 .venv/bin/python src/report/rules.py --vendor <기업> Makefile:14-15
    make judge-up 판정 서버를 로컬 8787 포트로 켜고 3초 뒤 /ping .venv/bin/uvicorn src.judge_api.app:app --host 127.0.0.1 --port 8787 (백그라운드, 로그 judge_api.log, 프로세스 번호 .judge.pid) Makefile:18-19
    make judge VENDOR=<기업> CALLS=2 ② 판정 모델 호출 .venv/bin/python src/judge_api/run_judge.py --vendor <기업> --calls-per-case 2 Makefile:25-26
    make judge-down 판정 서버 끄기 kill $(cat .judge.pid) 후 파일 삭제 Makefile:21-22
    make verdict VENDOR=<기업> ③ 판정 집계 .venv/bin/python src/report/verdict.py --vendor <기업> Makefile:29-30
    make all VENDOR=<기업> rules → judge → verdict 차례로(판정 서버는 먼저 켜 둘 것) — Makefile:33
    • 변수 기본값: VENDOR=funwave · CALLS=2 · PY=.venv/bin/python · UVICORN=.venv/bin/uvicorn (Makefile:3-6)

    한 기업을 처음부터 끝까지¶

    make rules   VENDOR=funwave
make judge-up
make judge   VENDOR=funwave CALLS=2
make judge-down
make verdict VENDOR=funwave
    • 판정 모델 없이도 rules → verdict만으로 돌아감 — 이때 판정 모델 몫 항목은 규칙 결과 그대로이거나 검토필요로 남음

    ② 판정 모델 호출 — src/judge_api/run_judge.py¶

    usage: run_judge.py [-h] --vendor {funwave,actibuki} [--input INPUT]
                    [--out OUT] [--calls-per-case CALLS_PER_CASE]
                    [--limit LIMIT] [--case-ids [CASE_IDS ...]] [--no-meta]
                    [--force] [--start START] [--cap CAP]
                    [--judge-url JUDGE_URL] [--cache-only]
    선택지 기본값 뜻
    --vendor (필수) funwave · actibuki
    --input data/inference_<기업>.parquet 기업 응답 파일
    --out data/judge_<기업>.parquet 결과 파일
    --calls-per-case 2 문항마다 판정 모델을 부르는 횟수
    --limit N 없음 앞에서부터 N 문항만(시험용). 액티부키는 일반 문항 · 변형 문항 각각 N개
    --case-ids A B ... 없음 이 문항만. 액티부키 변형 문항만 골라도 비교할 원문은 전체에서 찾음
    --no-meta 꺼짐 펀웨이브 /judge/meta 호출을 건너뜀
    --force 꺼짐 이미 있는 결과 파일을 무시하고 처음부터(결과 파일을 새로 씀)
    --start 4 클라이언트 처음 동시 호출 수
    --cap 16 클라이언트 동시 호출 수 상한
    --judge-url JUDGE_API_URL 또는 http://127.0.0.1:8787 판정 서버 주소
    --cache-only 꺼짐 raw/judge_client/에 남은 결과만 되살리고 새 호출은 하지 않음(사용 한도가 바닥났을 때)
    • 근거: src/judge_api/run_judge.py:190-205
    • 판정 서버가 켜져 있어야 함 — 시작할 때 /ping이 실패하면 judge API not reachable로 멈춤 (:218-221)

    무엇을 어디로 보내나¶

    기업 고르는 행 엔드포인트 근거
    펀웨이브 HTTP 200 · error 없음 · 필터에 막히지 않음 · 평가 항목(category의 + 앞부분)이 근거충실성/사실정확성 · 입력 및 반복 강건성(문항마다 첫 회차만) · 다국어 강건성(크로스) · 인젝션/맥락 조작 /judge/faithfulness :31, :66-73, :141-150
    펀웨이브 위 결과 중 1회차가 적정 + 동일상황이 아닌 문항 /judge/meta(1번) :302-315
    액티부키 HTTP 200 · error 없음인 행(문항마다 첫 회차) 중 P3 입력 강건성 변형이 아닌 것 /judge/rubric/actibuki :153-162, :240-243
    액티부키 P3 입력 강건성 변형(같은 group_id의 원문과 짝지음) /judge/robustness :244-251
    • 요청 본문을 만드는 곳: 펀웨이브 funwave_payload (:77-106) · 액티부키 actibuki_payload (:126-137)

    이어서 돌리기¶

    • 결과 파일에 이미 성공(ok=참)으로 있는 (case_id, run, call_idx, endpoint)는 다시 부르지 않음 (:212-216, :252)
    • raw/judge_client/에 HTTP 200 결과가 남은 호출도 다시 부르지 않고 되살림 (:262-283)
    • 실패했다가 다시 성공한 호출은 성공 기록만 남김 (:329-332)

    만드는 파일¶

    파일 내용 근거
    data/judge_<기업>.parquet 호출 1번 = 1행(입력과 출력 파일의 열) :333-335
    docs/judge_<기업>_run.md 실행 요약(호출 수 · 성공 · 오류 · 동시 호출 수 변화). 커밋 · 문서 사이트 제외 :336-338
    raw/judge_client/*.json 클라이언트 호출 원본 src/judge_api/client.py:18
    • 2회 결과 일치(self_consistent): 펀웨이브 faithfulness는 충실도 차이 10 이하, meta는 원인이 같음, 그 밖은 판정 값이 같으면 일치 (:341-356)

    주의할 점¶

    • 입력 파일의 run 열은 문자열로 넣을 것 — 판정 집계는 run이 비면 "v2"로, 실행기는 run 열이 없으면 1로 채워 서로 짝이 안 맞음 (src/report/verdict.py:510, src/judge_api/run_judge.py:207-208)
    • 실행기 결과를 판정 집계가 찾는 열쇠: (case_id, run, endpoint) (src/report/verdict.py:76, :512-517)
