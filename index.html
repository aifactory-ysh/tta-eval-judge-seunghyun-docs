    TTA 신뢰성 평가 판정 모듈 개발 문서¶

    이 쪽에서 알 수 있는 것

    • 이 모듈이 무엇을 하는지(응답 1건 → 실패 / 통과)와 세 단계
    • 기업 API · 판정 모델 없이 바로 돌려 보는 방법
    • 하려는 일별로 어느 쪽을 보면 되는지

    무엇¶

    • TTA 신뢰성 평가에서 기업 서비스의 응답 1건을 실패 / 통과로 가르는 코드만 떼어 낸 저장소
    • 평가 대상 두 곳
      • 액티부키: 관광 해설 RAG 챗봇(지식베이스(답의 근거 자료 묶음)를 찾아 답하는 챗봇)
      • 펀웨이브: 의료 통역 학습 서비스의 통역 채점 API(학습자가 입력한 통역문에 점수를 매김)
    • 작성 · 담당: 윤승현(seunghyun, ㈜인공지능팩토리 · 평가 용역사)

    왜 이렇게 나눴나¶

    • 기업 API를 부르지 않음 — 입력은 미리 받아 둔 기업 응답 파일. 판정만 다시 돌려 볼 수 있게 함
    • 같은 입력이면 같은 판정 — 이미 제출한 데이터셋의 판정을 만든 코드이므로 판정 값 · 판정 사유 문장이 바뀌지 않게 시험으로 고정(tests/)
    • 문항 생성 · 기업 API 호출 · 실제 자료는 들어 있지 않음(한계와 빠진 것)

    판정 값 표기

    • 이 문서는 서비스 쪽 표기만 씀: 실패 = 서비스가 잘못 동작, 통과 = 서비스가 바르게 동작
    • 결과 파일 · 판정 서버 응답의 값은 평가 설계 때 정한 코드 값(공격 쪽 말) — 용어 풀이의 대응표
    코드 값 서비스 쪽 표기
    성공 실패
    실패 통과(방어)
    정상 통과(정상 입력에 바른 응답)
    검토필요 검토필요(실패 · 통과를 가르지 못함)

    어떻게 — 세 단계¶

    flowchart LR
    IN["기업 응답 파일<br/>(미리 받아 둔 것)"] --> R["① 규칙 판정"]
    IN --> J["② 독립 판정 모델<br/>판정 서버 + 실행기"]
    R --> V["③ 판정 집계"]
    J --> V
    V --> OUT["최종 판정 +<br/>한국어 판정 사유"]
    단계 하는 일 외부 호출 코드
    ① 규칙 판정 응답의 필드 값 · 문자열을 정해진 조건으로 비교 없음 src/report/rules/
    ② 독립 판정 모델 규칙으로 가르기 어려운 응답을 언어 모델이 읽고 판정. HTTP 서버(판정 서버)를 실행기가 부름 판정 모델 API(가짜 판정 모델을 고르면 없음) src/judge_api/
    ③ 판정 집계 ①과 ②를 합쳐 호출마다 최종 판정 · 판정 사유를 냄 없음 src/report/verdict/

    예시 — 바로 돌려 보기¶

    make venv
make demo      # 지어낸 예시 입력으로 ① → ②(가짜 판정 모델) → ③, 외부 호출 0
    • 결과: build/demo/data/verdict_<기업>.parquet
    • 자세히: 빠른 시작

    문서 길잡이¶

    하려는 일 볼 곳
    기업 API · 판정 모델 없이 돌려 보고, 실제 판정 모델 붙이기 빠른 시작
    기업 응답 파일 전체를 판정하기(명령 · 선택지) 실행기와 명령
    응답 1건이 실패 / 통과 / 검토필요가 되는 과정 판정 흐름
    평가 항목별 실패 · 통과 조건과 문턱 값 기업별 판정 기준
    입력 파일에 넣을 열 · 결과 파일의 열 입력과 출력 파일의 열
    판정 서버 엔드포인트의 요청 · 응답 · 오류 엔드포인트 사용법
    낯선 말 용어 풀이
    고친 약점 · 선택지로 둔 것 · 못 고치는 것 한계와 빠진 것

    폴더 구성¶

    tta-eval-judge-seunghyun/
├── README.md               요약
├── Makefile                실행 명령(demo · rules · judge · verdict · test)
├── requirements.txt        실행에 필요한 패키지
├── requirements-dev.txt    시험 · 코드 검사용(pytest · ruff)
├── requirements-docs.txt   이 문서 빌드용
├── .env.example            환경 변수 이름(값은 비움)
├── examples/               지어낸 예시 입력(가상 관광지 · 평범한 진료 대화)
├── tests/                  회귀 시험(리팩토링 전 코드의 결과와 같은지)
├── docs/ · mkdocs.yml      이 문서
└── src/
    ├── common/             공용: 경로 · 환경 변수(config) · 판정 값 코드(verdicts) · HTTP 호출(http) · 표 도구(tabular)
    ├── report/
    │   ├── rules/          ① 규칙 판정: funwave.py · actibuki.py · common.py
    │   ├── verdict/        ③ 판정 집계: funwave.py · actibuki.py · text.py(사유 문장 도구)
    │   └── ko_labels.py    판정 사유 문장에 쓰는 한국어 이름표
    ├── judge_api/          ② 판정 서버(app) · 지시문(prompts) · 요청 · 응답 형식(schemas) · 판정 모델 호출부(backend) · 클라이언트 · 실행기
    └── demo.py             외부 호출 없는 데모
    • 실행하면 생기는 폴더(모두 .gitignore 대상): data/(입력 · 결과 · 실행 기록) · raw/(호출 원본) · build/demo/(데모 결과)
    • import 할 때는 폴더를 만들지 않음 — 쓰기 직전에 만듦

    이 문서 보는 법¶

    python3 -m venv .venv-docs
.venv-docs/bin/pip install -r requirements-docs.txt
.venv-docs/bin/mkdocs serve            # 127.0.0.1:8000 에서 보기
.venv-docs/bin/mkdocs build --strict   # site/ 에 정적 사이트(커밋하지 않음)
