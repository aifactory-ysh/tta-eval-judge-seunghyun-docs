    파이썬 클라이언트 JudgeClient¶

    • 위치: src/judge_api/client.py (:12-52)
    • 판정 서버를 비동기(asyncio)로 부르는 얇은 클라이언트. 실행기 run_judge.py도 이것을 씀
    • 동시 호출 수 자동 조절 · 다시 시도 · 호출 원본 저장은 src/common/core.py의 AdaptiveClient가 맡음

    만들기¶

    import sys
sys.path.insert(0, "src")            # 저장소 최상위에서 실행할 때
from judge_api.client import JudgeClient

c = JudgeClient(base_url=None, start=4, cap=16, timeout=900.0)
    인자 기본값 뜻 근거
    base_url 환경 변수 JUDGE_API_URL, 없으면 http://127.0.0.1:8787 판정 서버 주소 src/judge_api/client.py:16
    start 4 처음 허용하는 동시 호출 수 :13, :19
    cap 16 동시 호출 수 상한 :13, :20
    timeout 900.0 요청 1번의 제한 시간(초) :13, :21
    • 다시 시도: 최대 5번 시도(max_retries=5, :22) — 조건은 공통 사항 · 다시 시도
    • import 하면 저장소 최상위에 data/ · raw/ · docs/ · prompts/ · report/ 폴더가 생김 (src/common/core.py:27-33)
    • 판정 서버용 환경 변수(JUDGE_MODEL 등)는 필요 없음

    메서드¶

    메서드 부르는 엔드포인트 호출 원본 파일 이름(raw/judge_client/ 아래)
    await c.ping() GET /ping ping.json
    await c.faithfulness(payload, call_idx=1) POST /judge/faithfulness faithfulness_<case_id>_<call_idx>.json
    await c.rubric(vendor, payload, call_idx=1) POST /judge/rubric/{vendor} rubric_<vendor>_<case_id>_<call_idx>.json
    await c.meta(payload, call_idx=1) POST /judge/meta meta_<case_id>_<call_idx>.json
    await c.robustness(payload, call_idx=1) POST /judge/robustness robustness_<case_id>_<call_idx>.json
    await c.aclose() — 연결을 닫음. 다 쓰면 꼭 부를 것
    • 근거: src/judge_api/client.py:38-52
    • payload는 각 엔드포인트의 요청 본문(딕셔너리). case_id가 반드시 있어야 함(파일 이름에 씀)
    • call_idx: 같은 문항을 여러 번 판정할 때의 회차. 파일 이름에만 쓰이고 서버로는 가지 않음
    • 파일 이름의 영문 · 숫자 · . · _ · - 밖의 글자는 _로 바뀜 (src/common/core.py:65-66, :226)

    돌려주는 값¶

    • faithfulness · rubric · meta · robustness (src/judge_api/client.py:28-36)

      • 성공(2xx): 서버 응답 본문 + 아래 키
      키 뜻
      ok true
      client_latency_s 마지막 시도에 걸린 시간(초)
      attempts 시도 횟수(다시 시도 포함)
      • 실패(다시 시도해도 2xx가 아님, 또는 본문이 JSON 객체가 아님): 예외를 내지 않고 아래를 돌려줌
      키 뜻
      ok false
      error http_<상태 코드> · timeout:<예외 이름> · <예외 이름>:<메시지> · bad_body
      status 마지막 HTTP 상태 코드(연결 실패면 null)
      body 마지막 응답 본문(예: 422 · 502의 detail)
      latency_s 마지막 시도에 걸린 시간(초)

    • ping(): 응답 본문을 그대로, 실패하면 {"error": ...} (src/judge_api/client.py:38-40)

    여러 건을 한꺼번에¶

    import asyncio, sys
sys.path.insert(0, "src")
from judge_api.client import JudgeClient

pairs = [
    ("DEMO-RB-001-v1", "푸른숲고택의관람시간은언제인가요?"),
    ("DEMO-RB-001-v2", "푸른숲 고택의 관람 시간은 언제인가요??"),
]

async def main():
    c = JudgeClient(cap=4)
    ping = await c.ping()
    if not ping.get("ok"):
        raise SystemExit(f"판정 서버에 닿지 않음: {ping}")
    jobs = [
        c.robustness({
            "case_id": cid,
            "original_input": "푸른숲 고택의 관람 시간은 언제인가요?",
            "original_reply": "오전 9시부터 오후 6시까지 관람할 수 있습니다.",
            "variant_input": q,
            "variant_reply": "오전 9시부터 오후 6시까지예요.",
        })
        for cid, q in pairs
    ]
    for res in await asyncio.gather(*jobs):
        print(res.get("case_id"), res["ok"], res.get("verdict"))
    await c.aclose()

asyncio.run(main())
    • 동시에 몇 건을 보낼지는 클라이언트가 자동으로 조절함(cap 이하)

    주의할 점¶

    • 호출할 때마다 raw/judge_client/<파일 이름>.json에 요청 · 응답 전문을, data/usage_ledger.jsonl에 한 줄 기록을 남김 (src/common/core.py:193, :225-226) — 공유 · 커밋 금지
    • 같은 case_id · call_idx로 다시 부르면 같은 파일 이름에 덮어씀
    • 실행기는 이 파일을 "이미 받은 결과"로 되살려 씀(--cache-only, 실행기와 명령) — 다른 내용으로 같은 case_id를 시험 삼아 부르면 실행기 결과가 섞일 수 있음. 시험용 case_id는 실제 문항 식별자와 겹치지 않게
