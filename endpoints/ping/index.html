    GET /ping — 살아 있는지 확인¶

    이 쪽에서 알 수 있는 것

    • 판정 서버가 켜져 있는지 · 어떤 판정 모델(실제 · 가짜)로 떠 있는지 확인하는 법
    • 응답 필드(호출 통계 포함)의 뜻
    • 토큰을 설정했을 때 부르는 법

    무엇¶

    • 판정 서버의 상태 · 모델 이름 · 지금까지의 호출 통계를 돌려줌 (src/judge_api/app.py:208-213)
    • 판정 모델을 부르지 않음 — 사용 한도를 쓰지 않음
    • 요청 본문 · 쿼리 없음

    왜 — 언제 쓰나¶

    • 서버를 켠 직후(make judge-up이 3초 뒤 자동으로 부름, Makefile judge-up)
    • 실행기가 판정을 시작하기 전 1번. ok가 참이 아니면 멈춤 (src/judge_api/run_judge.py:354-356)
    • 긴 판정 도중 진행 · 오류 수를 볼 때

    어떻게 — 응답 필드¶

    • 응답 형식: PingResp (src/judge_api/schemas.py:151-159)
    필드 형 뜻 가능한 값
    ok 불 서버가 응답함 항상 true
    ts 문자열 서버 시각(UTC, ISO 8601, 밀리초까지) —
    judge_model 문자열 기본 판정 모델 이름(환경 변수 JUDGE_MODEL) 가짜 판정 모델이고 값이 비면 offline-fake-judge
    xling_model 문자열 교차 확인 모델 이름(JUDGE_MODEL_XLING) 위와 같음
    backend 문자열 판정 모델 종류(환경 변수 JUDGE_BACKEND) real(실제) · fake(가짜, 외부 호출 없음)
    stats 객체 서버가 켜진 뒤의 판정 수 · 오류 수(아래 표) —
    model_http 객체 또는 null 판정 모델 API 호출 통계(아래 표). 가짜 판정 모델이거나 아직 한 번도 부르지 않았으면 null —
    concurrency_limit 정수 또는 null 판정 모델 API에 지금 허용한 동시 호출 수(자동 조절 값). model_http가 null이면 null 처음 4
    • stats 안 (src/judge_api/app.py:43-44, :67, :117, :121, :137, :149-155)
    키 뜻
    faithfulness · rubric · meta · robustness 엔드포인트별로 판정 모델 결과를 받아 응답을 만든 횟수
    model_errors 502를 돌려준 횟수(판정 모델 호출 실패 · 출력 형식 오류)
    xling_mode JUDGE_XLING 값(on · off · auto). 서버 시작 처리 전이면 null
    xling_skipped 교차 확인을 건너뛴 횟수(최근 실패 뒤 대기 중이라서)
    xling_circuit_open 지금 교차 확인을 건너뛰는 중인지
    xling_errors 교차 확인 모델 실패 횟수 — 처음 실패한 뒤에만 나타남
    • model_http 안 (src/common/http.py:132, :164-189)
    키 뜻
    calls 판정 모델 API에 보낸 시도 수(다시 시도 포함)
    ok 2xx로 끝난 요청 수
    retries 다시 시도한 수
    fail 끝내 실패한 요청 수
    status 상태 코드별 횟수(예: {"200": 10, "429": 2}, 연결 실패는 "None")

    예시¶

    curl -s http://127.0.0.1:8787/ping
# JUDGE_API_TOKEN 을 설정했다면
curl -s -H "Authorization: Bearer $JUDGE_API_TOKEN" http://127.0.0.1:8787/ping

    # 저장소 최상위에서: .venv/bin/python 이 파일.py
import asyncio
from src.judge_api.client import JudgeClient

async def main():
    c = JudgeClient()                # 주소: JUDGE_API_URL 또는 http://127.0.0.1:8787, 토큰: JUDGE_API_TOKEN
    print(await c.ping())
    await c.aclose()

asyncio.run(main())

    {
  "ok": true,
  "ts": "<서버 시각>",
  "judge_model": "offline-fake-judge",
  "xling_model": "offline-fake-judge",
  "backend": "fake",
  "stats": {"faithfulness": 1, "rubric": 0, "meta": 0, "robustness": 0, "model_errors": 0,
            "xling_mode": null, "xling_skipped": 0, "xling_circuit_open": false},
  "model_http": null,
  "concurrency_limit": null
}

    판정 값 읽는 법¶

    • 판정 값 없음. ok가 true면 켜진 것
    • 판정이 자꾸 502로 끝날 때: stats.model_errors · model_http.status의 429 · 5xx 횟수를 볼 것
    • backend가 fake면 판정 결과는 시험용(실제 판정 아님)

    주의할 점¶

    • JudgeClient.ping()은 실패해도 예외를 내지 않고 {"error": ...}를 돌려줌 → ok 키로 확인 (src/judge_api/client.py:57-59)
    • stats.xling_mode가 null이면 서버 시작 처리(lifespan)가 돌지 않은 것 — uvicorn으로 띄운 서버는 값이 있음. TestClient를 with 없이 쓰거나 같은 프로세스 호출(in_process=True)이면 null
    • stats는 서버를 끄면 사라짐(메모리에만 있음)
    • 응답에 모델 이름이 들어 있음 → 결과를 밖으로 공유할 때 주의
