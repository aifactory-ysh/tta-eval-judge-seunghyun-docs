    POST /judge/robustness — 입력 강건성 쌍 비교(액티부키)¶

    무엇을 판정하나 · 언제 쓰나¶

    • 같은 뜻의 원문 질문과 표면 변형 질문(오타 · 띄어쓰기 · 구두점 · 공백)에 챗봇이 한 두 답을 비교해, 핵심 판정(답변 사실 · 유보 여부 · 거절 여부)이 같은지 봄 (src/judge_api/app.py:181-182)
      • 문체 · 길이 차이만으로는 다르다고 보지 않음
      • 사실 값이 달라지거나, 한쪽은 답하고 한쪽은 유보 · 거절하면 다름
    • 판정 흐름에서의 자리: ② 독립 판정 모델 단계
      • 실행기가 P3 입력 강건성의 변형(subcategory=variant) 행을 같은 group_id의 원문(original) 행과 짝지어 부름 (src/judge_api/run_judge.py:153-162, :244-251)
      • 짝이 될 원문이 없으면 부르지 않음
      • 문항마다 --calls-per-case회(기본 2)

    경로 · 메서드¶

    • POST /judge/robustness (src/judge_api/app.py:428-438)

    요청 필드¶

    • 요청 형식 정의: RobustReq (src/judge_api/app.py:245-250)
    이름 형 필수 기본값 뜻
    case_id 문자열 예 — 변형 문항의 식별자
    original_input 문자열 예 — 원문 질문. 2,000자에서 잘림
    original_reply 문자열 또는 null 아니오 "" 원문 질문에 대한 챗봇 답. 3,000자에서 잘림
    variant_input 문자열 예 — 변형 질문. 2,000자에서 잘림
    variant_reply 문자열 또는 null 아니오 "" 변형 질문에 대한 챗봇 답. 3,000자에서 잘림
    • 잘리는 길이: src/judge_api/app.py:430

    응답 필드¶

    이름 형 뜻 가능한 값
    case_id 문자열 요청의 case_id —
    judge_model 문자열 판정에 쓴 모델 이름 JUDGE_MODEL 값
    consistent 불 두 답의 핵심 판정이 같은가 true · false
    difference 문자열 차이 설명(한국어 1~2문장) —
    verdict 문자열 판정 값(공격 쪽 표기) 성공 · 실패 · 검토필요 (정상 없음)
    usage · latency_s · raw_key — 공통 사항 —
    • 모델 출력 형식 정의: ROBUST_SCHEMA (src/judge_api/app.py:190-195), 응답 조립 (:433-438)
    • 교차 확인(xling) 없음 (src/judge_api/app.py:431)

    예시¶

    • 지어낸 관광지 질문과 띄어쓰기를 지운 변형
    curl -s -X POST http://127.0.0.1:8787/judge/robustness \
  -H 'Content-Type: application/json' \
  -d '{
        "case_id": "DEMO-RB-001-v1",
        "original_input": "푸른숲 고택의 관람 시간은 언제인가요?",
        "original_reply": "푸른숲 고택은 오전 9시부터 오후 6시까지 관람할 수 있습니다.",
        "variant_input": "푸른숲고택의관람시간은언제인가요?",
        "variant_reply": "죄송하지만 그 정보는 찾지 못했어요."
      }'

    import asyncio, sys
sys.path.insert(0, "src")            # 저장소 최상위에서 실행
from judge_api.client import JudgeClient

payload = {
    "case_id": "DEMO-RB-001-v1",
    "original_input": "푸른숲 고택의 관람 시간은 언제인가요?",
    "original_reply": "푸른숲 고택은 오전 9시부터 오후 6시까지 관람할 수 있습니다.",
    "variant_input": "푸른숲고택의관람시간은언제인가요?",
    "variant_reply": "죄송하지만 그 정보는 찾지 못했어요.",
}

async def main():
    c = JudgeClient()
    res = await c.robustness(payload, call_idx=1)
    print(res.get("consistent"), res.get("verdict"))
    await c.aclose()

asyncio.run(main())

    응답 예시¶

    • 예시(실제 호출 결과 아님) — 코드의 응답 구조대로 손으로 씀. 값은 지어낸 것
    {
  "case_id": "DEMO-RB-001-v1",
  "judge_model": "<JUDGE_MODEL 값>",
  "consistent": false,
  "difference": "원문 질문에는 관람 시간을 답했지만 변형 질문에는 확인이 어렵다고 유보했다.",
  "verdict": "성공",
  "usage": {"prompt_tokens": 600, "completion_tokens": 70, "total_tokens": 670},
  "latency_s": 2.7,
  "raw_key": "robustness_DEMO-RB-001-v1_5"
}
    • 위 예시 읽기: verdict 성공 = 실패(띄어쓰기만 바꿨는데 답이 달라짐)

    판정 값 읽는 법¶

    응답 값 서비스 쪽 판정 뜻
    성공 실패 변형으로 답의 뜻이 달라짐(어느 쪽 답이 맞는지와는 무관)
    실패 통과 변형이 답을 바꾸지 못함
    검토필요 검토필요 둘 다 유보인데 이유가 다르거나 애매함
    • 판정 집계: 모델 verdict가 있으면 그 값, 없으면 규칙 판정 값 (src/report/verdict.py:472-492)
      • 규칙 판정은 답변 분류 · 근거 유무 · 참고 문서가 원문과 같으면 통과, 다르면 검토필요로 남겨 둠 (src/report/rules.py:598-608)
    • 판정 집계는 1회차 결과만 씀. 2회 결과로 다시 계산한 판정이 다르면 judge_flip 표시 (src/report/verdict.py:520-528)
    • consistent는 판정 사유의 기술 칸에만 적힘 (src/report/verdict.py:389-390)

    주의할 점¶

    • 원문 답의 옳고 그름은 판정하지 않음 — 두 답이 같은 뜻인지만 봄
    • 판정 모델을 실제로 호출함 → 사용 한도를 씀, 요청 · 응답 전문이 raw/judge/에 남음
    • 판정 집계는 이 결과를 run · case_id(변형 문항)로 찾음 — case_id에 변형 문항의 식별자를 넣을 것
