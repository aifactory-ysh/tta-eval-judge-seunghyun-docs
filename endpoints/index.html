    엔드포인트 사용법 — 공통 사항¶

    이 쪽에서 알 수 있는 것

    • 판정 서버(독립 판정 모델을 HTTP로 감싼 서버)의 엔드포인트 5개와 각각 언제 쓰는지
    • 모든 엔드포인트에 공통인 주소 · 인증(토큰) · 응답 필드 · 오류 응답 · 다시 시도 규칙
    • 외부 호출 없이 시험하는 방법(가짜 판정 모델 · 같은 프로세스 호출)

    왜 — 판정 흐름에서의 자리¶

    • 규칙 판정(글자 · 값 비교)으로 가르기 어려운 응답을 판정 모델이 읽고 판정함
    • 결과는 판정 집계(③ 단계, src/report/verdict/)가 규칙 판정과 합침 → 판정 흐름
    flowchart TD
    S["실행기 run_judge<br/>기업 응답 파일 읽기"] --> P["GET /ping<br/>시작할 때 1번"]
    P --> V{"기업"}
    V -- "펀웨이브" --> F["POST /judge/faithfulness<br/>문항마다 --calls-per-case 회(기본 2)"]
    F --> M{"1회차 결과가<br/>적정이고 동일상황인가"}
    M -- "아니오" --> MT["POST /judge/meta<br/>1번(--no-meta 면 건너뜀)"]
    M -- "예" --> END["judge_기업.parquet"]
    MT --> END
    V -- "액티부키" --> K{"P3 입력 강건성<br/>변형 문항인가"}
    K -- "아니오" --> RB["POST /judge/rubric/actibuki<br/>문항마다 --calls-per-case 회"]
    K -- "예" --> RO["POST /judge/robustness<br/>같은 묶음 원문 답과 짝지어<br/>--calls-per-case 회"]
    RB --> END
    RO --> END
    END --> AGG["③ 판정 집계가 읽음"]
    • 실행기의 대상 선택 · 호출 (src/judge_api/run_judge.py:159-208), 메타 평가 대상 (src/judge_api/run_judge.py:268-287)
    • 실행 명령 · 선택지: 실행기와 명령

    어떻게 — 인증(선택)¶

    • 환경 변수 JUDGE_API_TOKEN이 있을 때만 검사함 (src/judge_api/app.py:73-79)
      • 모든 경로(/ping 포함)가 헤더 Authorization: Bearer <토큰>을 요구
      • 없거나 틀리면 401 {"detail": "invalid or missing bearer token"}
    • 환경 변수가 없으면 검사하지 않음(예전과 같음)
    • 토큰과 별개로 기본 바인드는 127.0.0.1(로컬 전용) — 외부에 열면 판정 모델 사용 한도를 남이 쓸 수 있음
    • 클라이언트 · 실행기는 같은 환경 변수(또는 JudgeClient(token=...))로 토큰을 보냄 (src/judge_api/client.py:21-26)
    • 판정 서버 → 판정 모델 API 구간의 인증은 JUDGE_MODEL_API_KEY (src/common/http.py:198-210)
    export JUDGE_API_TOKEN=<아무 긴 문자열>
curl -s -H "Authorization: Bearer $JUDGE_API_TOKEN" http://127.0.0.1:8787/ping

    JudgeClient(in_process=True) 포트 없이 같은 프로세스 안의 판정 서버를 부름(네트워크로 나가지 않음) src/judge_api/client.py:28-32
    실행기 --in-process 위 클라이언트로 실행기 전체를 돌림 src/judge_api/run_judge.py:332

      • reasoning 등 글 필드 = "가짜 판정 모델(오프라인 시험용)의 응답입니다. 실제 판정이 아닙니다."
      • usage = null, latency_s = 0
    • 한 번에 돌려 보기: make demo (빠른 시작)

    응답 공통 — /judge/*¶

    • 성공하면 HTTP 200 + JSON 객체
    • 서버는 판정 모델이 낸 값을 바꾸지 않고 그대로 돌려줌. OpenAPI의 응답 형식은 문서용 (src/judge_api/app.py:205-206)
    • 모든 /judge/* 응답에 붙는 필드 (src/judge_api/schemas.py:68-75)
    필드 형 뜻 근거
    case_id 문자열 요청의 case_id 그대로 src/judge_api/schemas.py:71
    judge_model 문자열 판정에 쓴 모델 이름(환경 변수 JUDGE_MODEL) src/judge_api/schemas.py:72
    usage 객체 또는 null 판정 모델 API가 돌려준 토큰 사용량(prompt_tokens · completion_tokens · total_tokens 등). 가짜 판정 모델이면 null src/judge_api/schemas.py:61-65
    latency_s 숫자 판정 모델 호출 1번에 걸린 시간(초) src/judge_api/schemas.py:74
    raw_key 문자열 호출 원본 파일 이름의 열쇠. 위치 raw/judge/<raw_key>.json (실제 판정 모델일 때만 파일이 생김) src/judge_api/app.py:112-128
    • xling · xling_agree(교차 확인 결과) — /judge/faithfulness · /judge/rubric/{vendor}에만, 아래를 모두 채울 때만 붙음 (src/judge_api/app.py:131-156)
      • 요청 language가 zh 또는 ja
      • 환경 변수 JUDGE_XLING이 off가 아님
      • JUDGE_XLING=auto이면 최근 교차 확인 실패 뒤 건너뛰는 시간(JUDGE_XLING_COOLDOWN_S, 기본 600초)이 지났음
      • 교차 확인 모델 호출이 성공함
    • xling이 없을 때: "대상 아님"인지 "실패로 건너뜀"인지 응답만으로는 구분 못 함(실패 사유는 서버 안에서만 씀)
    • 판정 집계는 xling을 읽지 않음 — 기록용

    sequenceDiagram

    판정 서버 → 판정 모델(기본 모델) 8 같음 src/common/http.py:198, src/judge_api/backend.py:75
    판정 서버 → 교차 확인 모델 1(다시 시도 안 함) — src/judge_api/backend.py:73
    • 기다리는 시간 (src/common/http.py:108-115, :182-185)
      • 429이고 본문에 quota(사용 한도)가 있음: 15~30초 + 늘어나는 대기
      • 그 밖의 429: 2~3초 + 늘어나는 대기
      • 502: 0~0.5초
      • 503 · 504 · 시간 초과 · 500: 늘어나는 대기(1초에서 두 배씩, 최대 30초) + 0~1초
    • 그 밖의 4xx(400 · 401 · 404 · 422 등)는 다시 시도하지 않음
    • 동시 호출 수 자동 조절(AIMD: 성공하면 조금씩 늘리고 막히면 절반으로) (src/common/http.py:56-105)
      • 연속 8번 성공 → 상한 +1, 429 · 502 · 503 · 504 · 시간 초과 → 절반
      • 클라이언트 기본: 시작 4 · 최대 16 (src/judge_api/client.py:21)
      • 판정 서버 → 기본 모델: 시작 4 · 최대 JUDGE_MAX_CONCURRENCY(기본 24) / 교차 확인 모델: 시작 2 · 최대 4 (src/judge_api/backend.py:73-75, src/common/http.py:200)
    • 제한 시간: 클라이언트 → 서버 900초 (src/judge_api/client.py:21) · 서버 → 판정 모델 240초 (src/common/http.py:208)
