    엔드포인트 사용법 — 공통 사항¶

    엔드포인트 한눈에¶

    메서드 · 경로 쓰임 대상 기업 판정 모델 호출 쪽
    GET /ping 서버가 살아 있는지 · 호출 통계 확인 — 안 함 보기
    POST /judge/faithfulness 통역문의 의미 충실도를 독립 채점하고 기업 점수가 적정한지 평가 펀웨이브 함 보기
    POST /judge/rubric/{vendor} 챗봇 응답 1건을 평가 항목별 기준으로 판정 액티부키(vendor=actibuki만) 함 보기
    POST /judge/meta 기업 점수와 독립 판정 모델 결과가 어긋난 원인 분류 펀웨이브 함 보기
    POST /judge/robustness 원문 질문과 변형 질문에 대한 두 답의 뜻이 같은지 비교 액티부키 함 보기
    • 근거: 라우트 정의 src/judge_api/app.py:333, :338, :364, :415, :428
    • FastAPI가 자동으로 여는 경로(판정 모델 호출 없음)
      • GET /docs — 요청을 직접 보내 볼 수 있는 화면(Swagger UI)
      • GET /redoc — 읽기용 API 문서
      • GET /openapi.json — 요청 형식 정의(OpenAPI 3.1). 응답 형식은 비어 있음({}) — 응답 필드는 이 문서의 표를 볼 것

    판정 흐름에서 언제 쓰는가¶

    flowchart TD
    S["실행기 run_judge.py<br/>기업 응답 파일 읽기"] --> P["GET /ping<br/>시작할 때 1번"]

    MT --> END

    • 판정 집계가 각 결과를 쓰는 방식은 엔드포인트별 쪽의 "판정 값 읽는 법"과 판정 흐름

    기본 주소¶

    • 판정 서버: http://127.0.0.1:8787 (Makefile:19, src/judge_api/client.py:16)
    • 바꾸려면: 서버는 uvicorn의 --host · --port, 클라이언트 · 실행기는 환경 변수 JUDGE_API_URL 또는 실행기의 --judge-url

    요청 형식¶

    • POST 본문은 JSON, 헤더 Content-Type: application/json
    • 요청 본문 검사는 FastAPI(pydantic)가 함 — 표에 없는 필드는 무시됨(오류 아님)
    • 긴 글은 판정 모델에 넘기기 전에 잘림(뒤에 …). 잘리는 길이는 필드마다 엔드포인트 쪽에 적음 (src/judge_api/app.py:271-277)
    • 판정 모델 호출 조건: temperature 0 · 정해진 JSON 형식(strict JSON schema)으로만 답하게 함 · 최대 출력 3,000 토큰 (src/judge_api/app.py:282, src/common/core.py:276-277)

    인증¶

    • 없음 — 판정 서버에 인증 · 접근 제한 코드가 없음(src/judge_api/app.py 전체에 인증 의존성 · 미들웨어 없음)
    • 그래서 --host 127.0.0.1로만 띄울 것. 외부에 열면 누구나 판정 모델 사용 한도를 쓸 수 있음
    • 판정 서버 → 판정 모델 API 구간의 인증은 서버가 UNCENSORED_API_KEY로 처리 (src/common/core.py:237)

    응답 공통¶

    • 성공하면 HTTP 200 + JSON 객체
    • /judge/* 응답에 공통으로 붙는 필드
    필드 형 뜻
    case_id 문자열 요청에 넣은 case_id 그대로
    judge_model 문자열 판정에 쓴 모델 이름(환경 변수 JUDGE_MODEL 값)
    usage 객체 또는 null 판정 모델 API가 돌려준 토큰 사용량(prompt_tokens · completion_tokens · total_tokens 등, 제공 API 형식 그대로)
    latency_s 숫자 판정 모델 호출 1번에 걸린 시간(초)
    raw_key 문자열 판정 서버가 남긴 호출 원본 파일 이름의 열쇠. 파일 위치 raw/judge/<raw_key>.json. xling 안의 raw_key는 raw/judge_xling/<raw_key>.json (src/judge_api/app.py:258-260, :282, src/common/core.py:238, :226)
    • xling · xling_agree: 교차 확인 결과. /judge/faithfulness · /judge/rubric/{vendor}에만, 그리고 아래 조건을 모두 채울 때만 붙음 (src/judge_api/app.py:294-318)
      • 요청의 language가 zh 또는 ja
      • JUDGE_XLING이 off가 아님
      • JUDGE_XLING=auto일 때 최근 교차 확인 실패 뒤 건너뛰는 시간(JUDGE_XLING_COOLDOWN_S)이 지났음
      • 교차 확인 모델 호출이 성공함
    • xling이 없을 때 → "대상 아님"인지 "교차 확인 실패로 건너뜀"인지 응답만으로는 구분할 수 없음(실패 사유는 내부 키 _xling_error로만 남고 응답에서 빠짐, src/judge_api/app.py:300, :314, :352)
    • 판정 집계(verdict.py)는 xling을 읽지 않음 — 기록용

    오류 응답¶

    상태 코드 언제 본문 다시 보내면 되나
    422 필수 필드 누락 · 형이 틀림 · JSON이 아님 FastAPI 기본 형식 {"detail": [{"type", "loc", "msg", "input", ...}]} 아니오 — 요청을 고칠 것
    404 없는 경로, 또는 /judge/rubric/{vendor}의 vendor가 actibuki가 아님 {"detail": "..."} 아니오
    405 메서드가 틀림(예: POST /ping) {"detail": "Method Not Allowed"} 아니오
    502 판정 모델 호출 실패(서버 안에서 여러 번 다시 시도한 뒤), 또는 모델 답을 JSON으로 읽지 못함 {"detail": {"error", "model", "status", "text"}} (src/judge_api/app.py:283-285) 예 — 잠시 뒤 다시
    500 처리 중 예외. 코드상 예: 판정 모델이 낸 JSON에 필수 키가 빠짐(int(primary["meaning_fidelity"]) 등, src/judge_api/app.py:351) — 실제 발생은 확인하지 못함 FastAPI 기본(Internal Server Error) 클라이언트는 다시 시도함
    • 아래 422 · 404 · 405 본문은 판정 모델을 부르지 않는 경로에서 FastAPI TestClient로 실제 받은 값
    // POST /judge/faithfulness  본문 {}  → 422
{"detail": [
  {"type": "missing", "loc": ["body", "case_id"], "msg": "Field required", "input": {}},
  {"type": "missing", "loc": ["body", "input"], "msg": "Field required", "input": {}}
]}

// POST /judge/robustness  본문이 JSON 아님 → 422
{"detail": [{"type": "json_invalid", "loc": ["body", 0], "msg": "JSON decode error", "input": {}, "ctx": {"error": "Expecting value"}}]}

// POST /judge/rubric/funwave  (본문은 올바름) → 404
{"detail": "no rubric for vendor funwave; funwave rows use /judge/faithfulness"}

// POST /ping → 405
{"detail": "Method Not Allowed"}
    • 502 본문 예시(예시, 실제 호출 결과 아님 — 코드 src/judge_api/app.py:285의 구조대로 씀)
    {"detail": {"error": "http_429", "model": "<JUDGE_MODEL 값>", "status": 429, "text": ""}}
    • detail.error 값의 꼴 (src/common/core.py:181-183, :212, :216, :284, :294)
      • http_<상태 코드> — 판정 모델 API가 오류 상태를 줌
      • timeout:<예외 이름> — 판정 모델 API 응답 시간 초과(240초)
      • <예외 이름>:<메시지> — 연결 실패 등
      • bad_response:... — 응답에 choices가 없음
      • json_parse:... — 모델 답을 JSON으로 읽지 못함

    다시 시도¶

    sequenceDiagram
    participant C as 클라이언트 JudgeClient
    participant S as 판정 서버
    participant M as 판정 모델 API
    C->>S: POST /judge/... (최대 5번 시도)
    S->>M: POST /chat/completions (최대 8번 시도)
    M-->>S: 429 · 502 · 503 · 504 · 500 · 시간 초과면 기다렸다 다시
    S-->>C: 모두 실패하면 502
    C-->>C: 502 · 429 · 503 · 504 · 500 · 시간 초과면 기다렸다 다시
    구간 최대 시도(첫 시도 포함) 다시 시도하는 경우 근거
    클라이언트 → 판정 서버 5 429 · 502 · 503 · 504 · 시간 초과 · 500 src/judge_api/client.py:22, src/common/core.py:194-221
    판정 서버 → 판정 모델(주 모델) 8 같음 src/common/core.py:232, :194-221
    판정 서버 → 교차 확인 모델 1(다시 시도 안 함) — src/judge_api/app.py:260
    • 기다리는 시간 (src/common/core.py:203-213, :217-220)
      • 429이고 본문에 quota가 있음: 15~30초 + 늘어나는 대기
      • 그 밖의 429: 2~3초 + 늘어나는 대기
      • 502: 0~0.5초
      • 503 · 504 · 시간 초과 · 500: 늘어나는 대기(1초에서 시작해 두 배씩, 최대 30초) + 0~1초
    • 그 밖의 4xx(400 · 404 · 422 등)는 다시 시도하지 않음
    • 동시 호출 수 자동 조절 (src/common/core.py:98-143)
      • 연속 8번 성공하면 동시 호출 상한 +1, 429 · 502 · 503 · 504 · 시간 초과면 절반으로
      • 클라이언트 기본: 시작 4 · 최대 16 (src/judge_api/client.py:13)
      • 판정 서버 → 주 모델: 시작 4 · 최대 SHANNON_MAX_CONCURRENCY(기본 24) / 교차 확인 모델: 시작 2 · 최대 4 (src/judge_api/app.py:258-260)
    • 제한 시간: 클라이언트 → 서버 900초 (src/judge_api/client.py:13) · 서버 → 판정 모델 240초 (src/common/core.py:241)
