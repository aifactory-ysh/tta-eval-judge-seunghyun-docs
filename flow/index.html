    판정 흐름 — 응답 1건이 실패 / 통과 / 제외가 되기까지¶

    이 쪽에서 알 수 있는 것

    • 응답 1건이 거치는 단계와 갈림길(도식)
    • 평가 항목마다 판정 모델 결과를 쓰는지, 어떻게 쓰는지
    • 판정 흔들림(judge_flip)의 뜻과 선택지
    • 표기: 실패 · 통과는 서비스 쪽 표기(용어 풀이)

    무엇 — 전체 도식¶

    flowchart TD

    왜 두 갈래인가¶

    • 규칙: 같은 응답이면 늘 같은 결과, 빠름. 대신 글자 비교라 다른 말로 풀어 쓴 답 · 목록에 없는 거절 말투를 놓침
    • 판정 모델: 뜻을 읽고 판정. 대신 같은 문항도 회차마다 다를 수 있음 → 2회 돌려 흔들림을 표시

    "판정 모델 결과로 정함"의 뜻¶

    • 액티부키
      • 기본: 판정 모델이 낸 값을 그대로 씀. 규칙이 이미 실패 · 통과로 정한 행도 판정 모델 결과가 있으면 판정 모델이 이김
      • 선택지 --keep-rule-verdicts: 규칙이 정한 행은 규칙 결과 유지(실행기와 명령)
    • 펀웨이브(근거충실성만)
      • 판정 모델 충실도 · 기업 점수 평가와 규칙 결과를 정해진 순서로 합침 → 기업별 판정 기준

    판정 흔들림¶

    • 무엇: 판정 모델을 2회 이상 돌린 문항에서, 회차마다 최종 판정을 다시 계산해 서로 다른 것
    • 기록: judge_flip(참 · 거짓) · judge_verdicts_by_call(회차별 판정을 /로 이음) (src/report/verdict/__init__.py:105-115)
    • 판정 값
    선택지 흔들린 문항의 최종 판정
    --judge-policy first(기본) 1회차 결과
    --judge-policy agree 검토필요

    예시¶

    • 액티부키 거짓 전제 문항: 규칙은 "틀린 값이 사실처럼 등장" → 실패, 판정 모델 1회차는 "바로잡음" → 통과
      • 기본: 최종 통과
      • --keep-rule-verdicts: 최종 실패(규칙 유지)
      • 판정 모델 2회차가 실패였다면 judge_flip 참, --judge-policy agree에서는 검토필요

    이 저장소 밖¶

    • 정제 단계의 제외 · 판정 대기 분류는 이 저장소 코드에 없음(한계와 빠진 것)
