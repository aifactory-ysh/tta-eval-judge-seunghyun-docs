    용어 풀이¶

    이 쪽에서 알 수 있는 것

    • 판정 값 코드와 서비스 쪽 표기의 대응
    • 평가 · 판정 용어의 뜻
    • 코드 · 열 이름에 나오는 영문 이름의 뜻

    판정 값 표기¶

    • 결과 파일 · 판정 서버 응답 · 판정 사유 문장의 값은 평가 설계 때 정한 공격 쪽 말
    • 이 문서는 서비스 쪽 표기만 씀 — 아래 표로 바꿔 읽을 것
    • 대응은 코드 한 곳에서 관리 (src/common/verdicts.py:10-25)
    코드 값 서비스 쪽 표기 코드 안 이름
    성공 실패(공격이 통함 · 오류를 놓침 · 정상 입력을 잘못 막음) FAIL
    실패 통과(방어) PASS
    정상 통과(정상 입력에 바른 응답) NORMAL
    검토필요 검토필요 REVIEW
    호출 오류 호출 오류(판정하지 않음) CALL_ERROR
    • 코드 값을 바꾸지 않는 이유: 입력과 출력 파일의 열

    평가 용어¶

    용어 뜻
    문항 기업 서비스에 보내는 시험 입력 1개(액티부키는 질문, 펀웨이브는 통역문)
    호출 · 응답 문항 1개를 기업 API에 1번 보낸 것과 그 결과. 이 저장소는 받아 둔 응답만 읽음
    평가 항목 무엇을 시험하는지의 묶음. 열 category(예: 개인정보 노출/유출, P1 거짓 전제)
    세부 유형 평가 항목 안의 공격 · 변형 방식. 열 subcategory
    규칙 판정 응답의 필드 값과 문자열을 정해진 조건으로 비교하는 자동 판정. 같은 응답이면 늘 같은 결과
    독립 판정 모델 규칙으로 가르기 어려운 응답을 읽고 판정하는 언어 모델(기업 서비스와 무관). 코드 · 열 이름에서는 judge
    판정 서버 독립 판정 모델을 HTTP로 부를 수 있게 감싼 서버(FastAPI)
    가짜 판정 모델 외부 호출 없이 출력 형식에 맞는 값을 돌려주는 시험 · 데모용 대역(JUDGE_BACKEND=fake). 판정 품질과 무관
    실행기 기업 응답 파일을 읽어 판정 서버에 보내고 결과를 모으는 명령
    교차 확인 모델 중국어 · 일본어 행만 두 번째 모델로 한 번 더 판정해 보는 것(xling). 기록만, 판정에는 안 씀
    판정 집계 규칙 판정과 판정 모델 결과를 합쳐 호출마다 최종 판정 · 판정 사유를 내는 단계
    실패 서비스가 잘못 동작함
    통과 서비스가 바르게 동작함
    검토필요 규칙과 판정 모델로도 실패 · 통과를 가르지 못한 상태
    호출 오류 기업 API가 HTTP 200이 아닌 응답을 준 호출. 판정하지 않음
    문항 결함 문항을 만들 때의 오류로 시험이 성립하지 않는 문항(예: "틀린 값"이 실제 값과 같음). 판정하지 않음
    제외 · 정제본 검토필요 · 호출 오류 · 문항 결함 등을 뺀 최종 데이터. 만드는 코드는 이 저장소에 없음
    기대 범위 펀웨이브 통역문 변형마다 정해 둔 "기업이 줘야 할 의미 점수 구간". 입력 열 expected_meaning_range
    충실도 판정 모델이 매긴 통역문의 의미 충실도(0~100). 응답 meaning_fidelity
    기업 점수 평가 기업 의미 점수가 충실도보다 15점 넘게 높으면 과대, 낮으면 과소, 그 안이면 적정
    과잉 거부 막지 않아야 할 정상 입력을 서비스가 막거나 거절한 것
    지식베이스 액티부키 챗봇이 답의 근거로 찾는 자료 묶음
    정형 유보문 서비스가 모를 때 내는 정해진 한 문장. 규칙이 글자 그대로 비교함
    판정 흔들림 판정 모델 회차마다 다시 계산한 최종 판정이 다른 것. 열 judge_flip
    골든 비교 리팩토링 전 · 후 코드에 같은 입력을 넣고 결과를 행 단위로 견주는 것

    기업 · 코드 이름¶

    이름 뜻
    액티부키 · actibuki 관광 해설 RAG 챗봇 서비스 기업
    펀웨이브 · funwave 의료 통역 학습 서비스(통역 채점 API) 기업
    vendor 평가 대상 기업(영문 이름)
    case_id 문항 식별자
    run 같은 문항의 기업 API 호출 회차(없으면 "1")
    call_idx 같은 문항의 판정 모델 호출 회차
    rubric_kind /judge/rubric이 고른 기준 종류: faith 사실 질문 · absent 없는 관광지 · ood 도메인 외 · fp 거짓 전제 · inj 인젝션 · harm 유해 질의
    filtered · filter_reason 펀웨이브 API가 입력을 막았는지 · 막은 사유
    meaning · final 펀웨이브 API가 준 의미 점수 · 최종 점수
    intent · grounded 액티부키 응답의 답변 분류 · 근거 문서 있음 여부
    kb_value · false_value 지식베이스 정답 값 · 문항에 심은 틀린 값(또는 표식 문자열)
    JUDGE_BACKEND 판정 모델 고르기: real 실제 · fake 가짜
    model_http /ping 응답의 판정 모델 API 호출 통계
