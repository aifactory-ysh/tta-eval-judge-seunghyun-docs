    입력과 출력 파일의 열¶

    이 쪽에서 알 수 있는 것

    • 입력 파일(미리 받아 둔 기업 응답)에 넣어야 할 열
    • 규칙 판정 · 판정 모델 호출 · 판정 집계 결과 파일의 열과 뜻
    • 결과 열 이름이 공격 쪽 말로 남아 있는 이유

    무엇¶

    • 모든 파일은 parquet(표 형식 파일), 데이터 폴더(기본 data/, 환경 변수 EVAL_DATA_DIR) 아래. .gitignore 대상
    • <기업> = funwave 또는 actibuki
    • 예시 입력은 examples/inference_<기업>.json(지어낸 자료) — 데모가 parquet으로 바꿔 씀
    flowchart LR
    A["inference_기업.parquet<br/>입력: 기업 응답 1건 = 1행"] --> B["rules_기업.parquet<br/>입력 열 + 규칙 판정 열"]
    A --> C["judge_기업.parquet<br/>판정 모델 호출 1번 = 1행"]
    B --> D["verdict_기업.parquet<br/>기업 응답 1건 = 1행"]
    C --> D

    왜 결과 열 이름이 공격 결과인가¶

    • 판정 값 코드(성공 · 실패 · 정상 …)는 평가 설계 때 정한 공격 쪽 말
    • 이 코드가 판정 모델 지시문 · 판정 사유 문장 · 이미 제출한 결과 파일에 함께 들어 있음 → 바꾸면 모델 판정이 달라지거나 제출본과 어긋남
    • 그래서 열 이름 · 값은 그대로 두고, 코드 안에서는 서비스 쪽 이름(FAIL · PASS · NORMAL · REVIEW · CALL_ERROR)으로만 가리킴 (src/common/verdicts.py:10-25)
    코드 값 서비스 쪽 코드 안 이름
    성공 실패 FAIL
    실패 통과(방어) PASS
    정상 통과(정상) NORMAL
    검토필요 검토필요 REVIEW
    호출 오류 호출 오류 CALL_ERROR

    입력 — inference_<기업>.parquet¶

    • 행 1개 = 기업 API 호출 1번(이 저장소가 부른 것이 아니라 미리 받아 둔 것)
    • run(같은 문항의 호출 회차) 열이 없으면 실행기 · 판정 집계 모두 "1"로 봄
    기업 꼭 있어야 하는 열 있으면 쓰는 열
    공통 case_id · http_status · error · category · subcategory · attack_technique · group_id · input run
    펀웨이브 filtered · filter_reason · final · meaning · language_mismatch · language · role · expected_filter_reason · expected_meaning_range(JSON [하한, 상한]) · expected_final_range · expected_language_mismatch("True" · "mismatch_or_low" · "observe") · obfuscation · correct · comment_overall · actual_input_lang · terminology_score moderation_categories · moderation_flagged · similarity · source_text · perturbation_note · input_lang_expected · repeat_n · comment_expression · comment_medical_terms · terminology_json · harm_variant · inserted_text · base_input
    액티부키 reply · intent · grounded · kb_value · false_value · site · top_source_name · (반복 안정성 행) repeat_k · repeat_n attr_id · ood_topic · orig_case_id · sources_json · top_source_score · expected_behavior · expected_facts · expected_intent · language
    • 입력 열 → 판정 서버 요청 필드: 펀웨이브 src/judge_api/run_judge.py:87-114, 액티부키 src/judge_api/run_judge.py:117-145

    판정 모델 호출 결과 — judge_<기업>.parquet¶

    • 행 1개 = 판정 서버 호출 1번(같은 문항을 2회 부르면 2행) (src/judge_api/run_judge.py:214-241)
    열 뜻
    vendor · case_id · run · category · subcategory · attack_technique · language · group_id 입력 행에서 옮김
    call_idx 같은 문항 안의 판정 회차(1부터)
    endpoint faithfulness · rubric · robustness · meta
    original_case_id 입력 강건성 쌍 비교에서 짝지은 원문 문항
    ok · error 호출 성공 여부 · 실패 사유
    응답 필드를 풀어 쓴 열 meaning_fidelity · vendor_meaning_assessment · comment_accuracy · terminology_accuracy · correct_relevance · confidence · verdict · verdict_rule · rubric_kind · fact_coverage · hallucination · retrieval_ok · refused_or_hedged · fabricated · refused · partial_compliance · intent_ok · corrected · accepted_false · hedged · attack_success · asserted_false_value · marker_output · stayed_grounded · consistent · difference · discrepancy · cause · explanation · reasoning · xling_agree · judge_model · raw_key(엔드포인트에 없는 필드는 빈 값)
    errors_found · xling_json 오류 목록 · 교차 확인 결과(JSON 문자열)
    judge_prompt_tokens · judge_completion_tokens · judge_latency_s · client_latency_s 토큰 수 · 걸린 시간
    result_json 응답 전체(JSON 문자열). 풀어 쓴 열에 없는 필드(예: 유해 질의의 complied)는 여기에만
    ts 기록 시각
    self_consistent 같은 문항 회차별 결과가 일치하는가

    판정 집계 결과 — verdict_<기업>.parquet¶

    • 행 1개 = 입력 행 1개 (src/report/verdict/__init__.py:116-120)
    • 열 이름은 바뀌지 않았음(제출한 결과 파일 · 이 파일을 읽는 다른 도구와 맞춤)
    열 기업 뜻
    case_id · run 공통 문항 · 호출 회차(run이 없던 입력은 "1")
    공격 결과 공통 최종 판정(코드 값) — 성공=실패 · 실패=통과(방어) · 정상=통과(정상) · 검토필요 · 호출 오류
    final_verdict 공통 공격 결과와 같은 값
    평가사유 공통 한국어 판정 사유 문장. 코드 값으로 시작함(예: 성공(…) = 실패)
    평가프레임워크로 채점 공통 기술 상세(점수 · 판정 모델 값 등)
    rule_verdict 공통 규칙 판정 값
    category · subcategory · attack_technique · language · group_id 공통 입력에서 옮김
    judge_fidelity · judge_assessment · judge_comment_accuracy · judge_correct_relevance 펀웨이브 /judge/faithfulness 1회차 값
    meta_cause 펀웨이브 /judge/meta의 불일치 원인
    judge_verdict · judge_confidence · judge_fact_coverage 액티부키 /judge/rubric 또는 /judge/robustness 1회차 값
    judge_self_consistent 공통 회차별 결과 일치 여부
    judge_flip 공통 회차별로 다시 계산한 최종 판정이 갈리는가
    judge_verdicts_by_call 공통 회차별 최종 판정을 /로 이은 것
